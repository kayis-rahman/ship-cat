# Discord bridge

`src/discord-bridge-service.js` runs the separate queue-and-pull service intended for the Raspberry Pi. Start it with `node src/discord-bridge-service.js` after injecting `SHIPCAT_BRIDGE_HOST`, `SHIPCAT_BRIDGE_PORT`, `SHIPCAT_BRIDGE_TOKEN`, and `SHIPCAT_BRIDGE_QUEUE` into the process environment. The host must be an explicit loopback or private-network IP (RFC1918, Tailscale CGNAT, or IPv6 ULA); wildcard and public addresses and hostnames are rejected. The port defaults to 8765. Supply a runtime token of at least 32 bytes; the service does not load credentials from files or store them.

The service exposes authenticated pull and acknowledgement routes. `MacPuller` initiates outbound HTTP requests only, and restricts its destination to an explicit loopback or private-network IP and port. Inbox handling, audio retrieval, and local transcription are injected by the Mac-side caller. Voice processing has no hosted fallback and removes the returned temporary audio file after transcription succeeds or fails. Inbox request IDs are stable; the pull cursor is atomically persisted only after successful acknowledgement.

The implementation contains no Discord account credentials, Gateway client, bot API integration, deployment/start behavior, or production TLS. Tests use synthetic events and local loopback only; they do not contact a Pi, Discord, or an external service. Do not run the service or configure credentials as part of development testing.
